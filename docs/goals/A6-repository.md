# A6. Repository and environment

A monorepo; Julia 1.13 (the current release) as the target, CI on 1.13 with the next pre-release as allowed-fail; MIT; public from day one (so no private packages, no hostnames anywhere in the repo, including its `CLAUDE.md`); CI on the KA CPU backend, GPU tests on the local GPU runner. Layout: a Pkg workspace with the umbrella package at the root and `test/`, `docs/`, `benchmark/` and the `lib/` subpackages as members (factory setting F1; `lib/` is the pattern EDM uses for `lib/RunManifests`), `scripts/` and `reports/` for results (factory setting F3), `docs/plan/` for these documents, `.claude/agents` and `.claude/workflows`, `trace/`, `questions/`.

Relation to EDM: no dependency on ElectronDynamicsModels.jl initially; depend directly on its small public pieces, LaserTypes.jl and GPUDiagnostics.jl (both public GitHub repositories), and lift `RunManifests` out of EDM's `lib/` into its own package or into this monorepo's `lib/`; take the EDM dependency later if enough of it is needed or the symbolic layer earns its place.

Name: **`ParticleMesh.jl`** for the repository and the engine, repository https://github.com/SebastianM-C/ParticleMesh.jl (public); agents work in worktrees inside it, under `.claude/worktrees/`. The worktree is created by whoever starts the session, not by the session through EnterWorktree: that tool brings a git isolation guard in Claude Code which refuses ordinary commands (chains, heredocs, `sed` scripts, anything mentioning git), so the factory launchers run `git worktree add` themselves and start the session inside, and only interactive sessions still use EnterWorktree and live with the guard. A workaround for a Claude Code issue, to be dropped when the guard is fixed. Rationale: it names the method family (PIC, PM, P³M, PME) in the SciML style of naming packages after the method (MethodOfLines, NonlinearSolve), it is neutral to the physics so the modules carry the physics names (`Wakefields` for LWFA, a gravity PM module as the near-free generality demo), it is free in General and on GitHub (registry and GitHub availability checked 2026-10-30), and the term already means "differentiable particle–mesh simulation" to the cosmology community through pmwd, which is a positive association rather than a collision; the nearest neighbours are `flatironinstitute/ParticleMeshEwald.jl` (PME via NonuniformFFTs, unregistered) and, outside Julia, pmwd ("particle-mesh with derivatives", the differentiable cosmological PM library) and the Python package pmesh. Rejected: `Wakefields.jl` (too narrow for the umbrella after A9) and `DiffPIC` ("Diff-PIC" is an ICLR 2025 paper, a diffusion-model surrogate for laser-plasma PIC from PNNL and Rochester, so the name would be confusable within the same community). Caveat: mesh-free modules (pairwise interactions, FMM, analytic external fields) are hosted by the engine but not named by it; if those weigh more than expected, `ParticlesAndFields.jl` covers everything at the cost of being vaguer. Subpackage names follow the SciML `lib/` pattern (`ParticleMeshCore`, `ParticleMeshMTK`, `ParticleMeshReactant`, `Wakefields`).
