# A9. Scope: a generic particle–mesh framework

Long term the project is a showcase and stress test for Julia and Reactant compiler technology, with modular physics (extensible, possible EDM integration) and connections to packages such as Molly.jl to be explored; all of it long term. Consequences now, none of which change the phase 1–3 schedule: the engine/physics-module split, proven by the electromagnetic module, which is the only physics module planned (`architecture-draft.md` §0.1): no electrostatic module, because electrostatic PIC is of little interest on its own; electrostatic cases such as Landau damping and the two-stream instability run as edge cases of the electromagnetic module, with no transverse fields, as Smilei runs them; the Reactant-compatibility rules for every kernel (§0.4), with the Reactant CPU smoke test in CI once Reactant is unparked (below); the particle-workload stress-test suite as a deliverable (§0.2); the name (A6). Everything else in §0 is deferred (C). The main integration goal is SciML; Molly compatibility is a nice-to-have, not a design driver. FastMultipole.jl (CUDA for direct interactions only) is not needed for LWFA.

Reactant is parked for now: Reactant 0.2 requires GPUCompiler 1 and KernelAbstractions 0.9, while current CUDA.jl is on GPUCompiler 2 and KernelAbstractions 0.10, and the engine follows CUDA.jl. No package in the repository depends on Reactant until a Reactant release supports GPUCompiler 2 and KernelAbstractions 0.10; the package manager checks for that weekly and opens an issue when it happens, and the smoke test then starts. Meanwhile the §0.4 rules still bind every kernel, so the path stays open.

Once unparked, when the Reactant smoke test, or any Reactant path, fails because of Reactant itself rather than our kernel: open an `upstream` issue with a minimal reproducer, mark that test `@test_broken` with the issue number next to it, and move on. The Reactant feature it exercises stays parked until upstream is fixed; nothing works around it. This applies only when the native CPU test of the same kernel passes, and the reason the failure is upstream is written down in the issue; a failure in our own kernel is fixed, not marked broken.
