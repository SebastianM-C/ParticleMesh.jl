# Reports

Markdown reports with their figures committed next to them, one directory per report. A report is a record, not prose: it starts with a header block naming the work package, the commit, the run ids and the hashes of its inputs, and, once an independent review has run, a Review row (reviewer role, model id, date, findings file, the findings committed next to the report and each answered in it); then setup, results (figures from `scripts/` with their sidecar numbers), verification status, and open issues. A report cites the run manifests it rests on and the work package it belongs to. Benchmark numbers and scientific claims get an independent review before a report is cited outside the repository.

A report is about a page. It has a summary of at most ten lines, the header block, one table of final results, what is not shown, and where the data is. Its tables are printed by the tool that made the data (for the LWFA comparisons, `scripts/lwfa/lwfa.jl table`) and pasted unchanged, with a test that holds the text to the data where the tool has one. Tables per output, derivations and the definitions of measures stay in the JSON sidecars and in the code's docstrings, which the report names. Earlier run sets and earlier versions of the text go in commit messages. A review checks the numbers against the data and the summary's claims against the numbers; a finding is answered by correcting or removing a sentence, not by adding a qualifier to it.
