# Scripts: user code that produces results

Everything here uses the package the way a user would, to produce result artifacts: benchmark cases with their expected values, validation and cross-code comparison runs, campaigns and parameter sweeps (`campaigns/`), and the figures and numbers that `reports/` embed. It is its own Pkg environment, outside the root workspace, with a committed `Manifest.toml` so that a run is reproducible from the commit alone: `julia +1.13 --project=scripts <script>` after `Pkg.instantiate()`.

Conventions (F3 in `docs/plan/factory-and-observability.md`): outputs go to `scripts/runs/` (ignored), every run writes its manifest next to them, a run's bulk data reaches a report through its run branch (`rundata/run-data.sh`), and every plot is a CairoMakie PNG with its JSON sidecar. Any pull request may add a dependency here (F2); re-resolve this manifest whenever the root one changes.

`gpu-lock.sh` serializes GPU use between agents on one machine. `gpu-queue.sh` does the same as a queue: jobs wait in priority order and start within seconds of each other, and a test suite run with `PM_GPU_HOLD` waits only for its GPU testsets (the script's header; T-1210, T-1211). Both take the same lock file.

`digest/digest.jl` shows that a change of the electromagnetic module's state or step layer changes no run result: it hashes the full state and the histories of 23 short 1D and 2D runs and of two harness cases per element type and deposition mode, and its output from the old tree and from the new one, both on one machine, must be the same lines. It runs in the module's test environment, which picks the tree: `julia +1.13 --project=<tree>/lib/ParticleMeshElectromagnetic/test scripts/digest/digest.jl <out.txt> [modes] [cases]` (its header says what not to compare; T-746 runs two of its cases).

`ionization/` holds the figures and tables of the field ionization (WP-059, WP-063): `ionization.jl` makes those of `reports/wp-059-field-ionization.md`, `barrier_suppression.jl` those of `reports/wp-063-barrier-suppression.md`, and `fbpic_reference.py` writes the rates FBPIC's coefficient lines give (`lib/Wakefields/test/fbpic_reference.toml`, which T-783 compares against). The unit layer they use, the ionization energies of an element and their conversion to the normalized numbers of an `ADKLevel` or a `TongLinLevel` for a laser wavelength (A1), is in `lib/Wakefields`, with the fitted numbers of Tong and Lin's factor in its `data/tong_lin.toml`.
